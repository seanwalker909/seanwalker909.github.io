Platform Overview

Host: nvm3 · Raspberry Pi 5 Model B Rev 1.1 · Debian 13 (trixie) · kernel 6.18.39+rpt-rpi-2712

Hardware

Component Spec
SoC Raspberry Pi 5, 4× Cortex-A76 (aarch64)
RAM 8 GB (7.9 GiB visible)
Storage 1 TB NVMe SSD (HAT), 939 GB usable, ~19% used at capture
OS Debian 13, RPi-Imager-provisioned (cloud-init instance rpi-imager-1785247424630, image created 2026-07-28, most recent reprovision 2026-10-01)
Container runtime Docker 29.8.0 + containerd
Desktop Labwc Wayland compositor (LightDM) + Xwayland + Pipeewire

The Pi 5's NVMe interface and 8 GB of RAM let this box run a full service fleet that would normally need a mini-PC: a media platform, a photo platform with ML, a local AI stack, and an automation engine — all on consumer hardware, all on one power bill.

Network

  • LAN: 172.16.0.0/16, host at 172.16.0.229 (DHCP)
  • Docker bridge networks: one per service group (br-*), plus a shared external web-proxy network for reverse-proxied apps
  • Public reachability: DuckDNS (*.b0g0.duckdns.org) + Nginx Proxy Manager (TLS)
  • DNS: Pi-hole FTL v6.4.3 running locally; upstream via router 172.16.0.1

Why this matters (engineering signal)

  • Full-stack ownership: one engineer designs, provisions, secures, monitors, and operates every layer — hardware → OS → containers → apps → observability.
  • Production discipline at home scale: declarative compose files, per-service network isolation, loopback-only binding for internal helpers, nightly credential backups, metrics + dashboards, and a live agent layer for day-2 operations.
  • Breadth under constraint: 8 GB RAM on ARM64 forces real resource discipline (shared postgres, valkey, tmpfs caches) — the same constraints that matter in a cloud cost review.
