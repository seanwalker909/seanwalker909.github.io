Security & Networking

Edge

  • Nginx Proxy Manager (80/81/443) terminates TLS for the public-facing apps, with automated certificate issuance; host definitions per app.
  • DuckDNS (*.b0g0.duckdns.org) provides stable public names for a dynamic LAN IP.
  • HTTP redirects to HTTPS at the proxy layer; webhook endpoints (n8n) configured with N8N_PROTOCOL=https and proxy-hops awareness (N8N_PROXY_HOPS=1) so signatures and callbacks survive the proxy.

DNS & network

  • Pi-hole FTL v6.4.3 (systemd + cron) — local DNS with ad/tracker filtering; the machine also acts as the network's resolver for its own LAN.
  • One Docker bridge network per service group; shared services (Immich stack) on a group network; web-proxy external network for proxied apps. No service publishes internal ports to the host interface.
  • No WireGuard server currently; offsite sync uses SSH with a dedicated key (/root/.ssh/id_ed25519) — the pattern is ready for a VPN if a remote access path is needed.

Credentials & secrets

  • Vaultwarden as the single password store; its data directory is the subject of the nightly AES-256 (PBKDF2) encrypted, offsite rsync backup (see observability-ops) — plaintext never leaves the box.
  • API keys/tokens kept in per-service env/config files outside version control; the Hermes agent's secrets follow the same convention (~/.hermes/.env, settings in config.yaml).

Why this matters

The same four instincts that show up in SOC2/FedRAMP work at previous employers — least exposure, encrypted at rest, offsite redundancy, key-based auth — applied consistently on personal infrastructure.
